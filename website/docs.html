Cord Documentation

Cord is a modern, domain-specific programming language engineered specifically for Discord bot development. It eliminates async boilerplate, decorator nesting, and framework overhead while providing first-class language constructs for UI components, moderation, persistent storage, and background automation.

💡 Why a Dedicated Language?
General-purpose languages (Python, JavaScript) require 40+ lines of plumbing to declare a simple button menu with interaction tokens. Cord handles Discord gateway lifecycle, interaction tokens, and intent validation natively, letting you write clean, declarative code.

Unified Beginner & Developer Modes

Cord bridges the gap between novice creators and senior software engineers:

  • Beginner Mode: Readable English-style event triggers (when someone joins:), action keywords (reply, send #welcome), and clear diagnostic error messages.
  • Developer Mode: Expressive control flow, typed parameters (target: Member), permission security guards, built-in SQLite persistence (store), async HTTP (fetch), and modular imports.

Both styles share the exact same grammar and tree-walking interpreter. You can mix them freely in the same .cord file.

Installation & Prerequisites

Cord requires Python 3.10 or newer. You can install Cord using pip or run it isolated with pipx:

Terminal 
pip install cord-lang

Or install the development version directly from GitHub:

Terminal 
git clone https://github.com/mannansainicyber-dev/cord-lang.git
cd cord-lang
pip install -e .

Verify that the CLI is correctly installed:

Terminal 
cord --version
# Output: Cord 0.2.0 (Python 3.12.3)

60-Second Quickstart

Cord includes a built-in project scaffolding tool that generates a production-ready starter workspace:

Terminal 
cord init my-first-bot
cd my-first-bot

This scaffolds the following directory tree:

Structure
my-first-bot/
├── bot.cord       # Bot source code
├── .env.example   # Environment template
├── .gitignore     # Git ignore patterns
└── README.md      # Project overview

Writing Your First Bot (`bot.cord`)

Open bot.cord and define your bot:

bot.cord 
bot "GreeterBot"

config:
    prefix = "!"
    status = "online"
    activity = "with Cord"

when someone joins:
    send #welcome "Welcome {member.mention} to our community!"

command ping:
    reply "Pong! Latency is {bot.latency}ms"

command greet(target: Member = null):
    user = target or author
    reply "Hello, {user.mention}!"

Launch your bot with hot reload enabled:

Terminal
cord run bot.cord

Project Layout & Environment Variables

Cord looks for a .env file in your working directory to read the Discord Bot Token:

.env
DISCORD_TOKEN=MTE5OD...your_bot_token_here
📌 Required Discord Gateway Intents
To receive join events and prefix commands, enable the following in the Discord Developer Portal under your Bot tab:
  • Message Content Intent (for prefix commands)
  • Server Members Intent (for when someone joins:)

Indentation & Lexical Grammar

Cord uses the off-side rule (like Python and YAML). Blocks are defined by indenting 4 spaces.

  • Indent Depth: Strictly 4 spaces per block level.
  • Comments: Begin with # and continue to the end of the line.
  • Channel References: Any word prefixed by # (e.g. #welcome, #mod-logs) is parsed as a typed channel reference.

Types, Literals & Durations

Cord supports first-class literals tailored for bot development:

Literal Example Description
Integer 0, 42, -10, 1_000_000 Signed 64-bit integer with optional readability underscores.
Float 3.14, 0.001 Double-precision IEEE 754 floating point numbers.
Duration 500ms, 5s, 30m, 2h, 7d Native time spans used in timeouts, cooldowns, and tasks.
String "Hello {name}", 'single' UTF-8 text with inline expression interpolation.
Boolean true, false Standard boolean truth values.
Null null Null value / empty reference.
List [1, "two", 3.0] Ordered heterogeneous dynamic array.
Map {"coins": 100, "vip": true} Key-value associative mapping.

String Interpolation

Any valid Cord expression enclosed in curly braces {...} inside double quotes is evaluated in scope:

Cord
user_name = "Alex"
reply "Hello {user_name}, you have {store.coins.get(author.id, 0)} coins!"

Control Flow & Loops

Cord supports standard structured control flow:

Conditionals
if score >= 100:
    reply "🏆 Master Tier"
elif score >= 50:
    reply "🥈 Silver Tier"
else:
    reply "🥉 Novice"
Loops
for item in ["Alpha", "Beta", "Gamma"]:
    send #logs "Deploying {item}..."

count = 3
while count > 0:
    count -= 1

User Functions (`fn`)

Declare reusable functions with the fn keyword:

Functions
fn calculate_tax(amount, rate=0.05):
    return amount * rate

command purchase(price: Integer):
    tax = calculate_tax(price)
    total = price + tax
    reply "Total with tax: ${total}"

Bot & Config Declarations

Every bot begins with a bot declaration and optional config: block:

bot.cord
bot "Sentinel"

config:
    prefix = "!"
    status = "dnd"            # online | idle | dnd | invisible
    activity = "over the server"

Dual-Modality Commands

By default, every command name: is registered as both a Discord Slash Command (/name) and a Prefix Command (!name).

💡 Restricting Modality
If you want a command to only work as a slash command or only with a prefix, prepend slash or prefix: 
slash command ban(target: Member): ...
prefix command secret: ...

Typed Arguments & Signatures

Cord validates command arguments automatically before invoking the body:

Signatures
command warn(target: Member, reason: String = "No reason", severity: Integer = 1):
    reply "Warned {target.name} for '{reason}' (Level {severity})"

Supported type annotations:

  • Member: Guild member (resolves from mention, username, or ID).
  • User: Discord user account.
  • Channel: Text or voice channel reference.
  • String: Text string.
  • Integer: Integer number.
  • Float: Floating-point decimal.
  • Duration: Natural duration (e.g. 10m, 2h).

Declarative Permissions & Cooldowns

Protect sensitive commands declaratively without nested `if` statements:

Guards
command purge(count: Integer = 10):
    require permission manage_messages
    cooldown 10s per guild
    # Purge logic here

Events & Triggers

Cord features human-readable event phrases:

Events
when someone joins:
    send #welcome "👋 Welcome {member.mention}!"

when someone leaves:
    send #logs "Goodbye {member.name}."

when someone sends a message:
    if "badword" in message.content:
        delete message
        reply "⚠️ Please mind your language, {author.mention}."

Replies & Declarative Embeds

Construct rich embeds using clean indentation instead of dictionary objects:

Embeds
command profile:
    reply embed:
        title "User Profile: {author.name}"
        description "Community veteran & code contributor."
        color "#5865F2"
        thumbnail author.avatar_url
        field "Joined Server" author.joined_at inline=true
        field "Roles" len(author.roles) inline=true
        footer "Cord Language Engine"

Interactive UI Components

Buttons and Select Menus are declared directly inside a with: block attached to any reply or send statement.

💡 Zero Subclassing
You never write custom discord.ui.View subclasses. Cord binds component custom IDs directly to top-level event handlers.

Buttons & Button Styles

Buttons are declared using button "<id>"::

Buttons
reply "Portal options:" with:
    button "btn_verify":
        label "Verify Member"
        style "success"
        emoji "✅"
    button "btn_delete":
        label "Delete Ticket"
        style "danger"
        emoji "🗑️"
    button "btn_docs":
        label "Open Docs"
        style "link"
        url "https://cord-lang.org"

Supported button styles:

  • "primary": Blurple standard action button
  • "secondary": Neutral grey button
  • "success": Green confirmation button
  • "danger": Red destructive button
  • "link": External URL redirect button

Select Menus (Dropdowns)

Dropdowns are declared using select "<id>"::

Select Menus
reply "Pick specialization:" with:
    select "role_dropdown":
        placeholder "Choose your role..."
        min_values 1
        max_values 1
        option "engineer":
            label "Software Engineer"
            description "Builds backend systems"
            emoji "💻"
        option "designer":
            label "UI/UX Designer"
            description "Designs client interfaces"
            emoji "🎨"

Component Event Handlers

Handle user clicks and choices with top-level event handlers:

Component Handlers
when button "btn_verify" is clicked:
    author.add_role("Verified")
    reply "✅ Verification complete for {author.mention}!"

when select "role_dropdown" is chosen:
    author.set_role(selected)
    reply "Updated specialization to **{selected}**!"

Native Moderation Primitives

Cord provides dedicated, first-class language statements for server moderation actions: ban, kick, timeout, and unban.

The `timeout` Statement

Applies a communication timeout to a member using natural duration syntax:

timeout
command mute(target: Member, duration: Duration = 10m, reason = "Rule violation"):
    require permission moderate_members
    timeout target for duration reason=reason
    reply "🔇 Timed out {target.name} for {duration}."

The `ban`, `kick`, and `unban` Statements

Moderation
command banish(target: Member, reason: String = "Severe violation"):
    require permission ban_members
    ban target reason=reason
    reply "🔨 Banned **{target.name}**."

command pardon(user_id: String, reason: String = "Appeal granted"):
    require permission ban_members
    unban user_id reason=reason
    reply "🕊️ Unbanned {user_id}."

Audit Logs & Moderation Escalation

All moderation statements automatically register the given reason in the official Discord Server Audit Log.

The `fetch()` Built-in Function

Cord embeds an asynchronous HTTP client directly into the runtime. No aiohttp or requests packages required.

fetch
command quote:
    res = fetch("https://dummyjson.com/quotes/random")
    if res.ok:
        reply "\"{res.quote}\" — **{res.author}**"

The `http` REST Client Namespace

For complete REST workflows:

  • http.get(url, [headers], [params])
  • http.post(url, [json], [headers])
  • http.delete(url, [headers])
POST Request
payload = {"event": "login", "user": author.name}
res = http.post("https://my-api.internal/events", json=payload)

Dot-Notation JSON Proxy

Returned JSON maps allow intuitive dot notation directly on the response object:

Dot Notation
res = fetch("https://api.github.com/repos/mannansainicyber-dev/cord-lang")
reply "Stars: {res.stargazers_count} | Forks: {res.forks_count}"

Zero-Config Persistent SQLite Store

Every Cord bot includes an embedded, persistent SQLite document and key-value store accessible via the store keyword. Data persists across bot restarts in .cord_store.db without any database configuration.

store
# Store a value
store.balances[author.id] = (store.balances.get(author.id, 0)) + 100

# Retrieve with fallback
coins = store.balances.get(author.id, 0)

Store Operations & Dictionaries

Operation Syntax Description
Read Key store.key or store.get("key", default) Retrieves stored value with optional fallback.
Write Key store.key = value Persists value atomically to SQLite.
Check Key store.has("key") Returns true if key exists in store.
Delete Key store.delete("key") Removes key from store.

Background Scheduled Tasks

Automate recurring tasks without asyncio loops or cron daemons:

Tasks
task health_monitor every 15m:
    res = http.get("https://api.internal/health")
    if not res.ok:
        send #dev-alerts "🚨 Health check failed! HTTP {res.status}"

Multi-File Modular Imports

Split large bots into maintainable modules:

bot.cord
import "./modules/moderation.cord"
import "./modules/economy.cord"
import "./utils/helpers.cord"
🛡️ Cycle Protection
Cord tracks imported modules during resolution and prevents circular import deadlocks automatically.

Interactive REPL Shell: `cord repl`

Start an interactive read-eval-print loop to test expressions, built-ins, and AST evaluation:

Terminal
cord repl
cord > format_coins = fn(x): return "${x:,}"
cord > format_coins(50000)
"$50,000"

Offline Static Linter: `cord check`

Validate code syntax and indentation before gateway connection:

Terminal
cord check bot.cord
# Output: ✓ Success: No syntax or type errors found in 42 lines.

Production Containerization: `cord docker`

Generate multi-stage Dockerfiles and docker-compose configurations in one command:

Terminal
cord docker --compose
docker compose up -d

Production Recipe 2: Moderation Automod Shield

automod.cord 
bot "Shield"

when someone sends a message:
    if "discord.gg/" in message.content:
        delete message
        store.warns[author.id] = (store.warns[author.id] or 0) + 1
        warns = store.warns[author.id]

        if warns >= 3:
            timeout author for 1h reason="3+ invite link warnings"
            send #mod-logs "Timed out {author.name} for 1 hour."
        else:
            reply "⚠️ Warning {warns}/3: Discord invites are forbidden."

Production Recipe 4: Server Economy & Daily Claims

economy.cord 
bot "Vault"

command daily:
    cooldown 24h per user
    store.wallet[author.id] = (store.wallet.get(author.id, 0)) + 200
    reply "💰 Claimed 200 gold! Balance: {store.wallet[author.id]}"

command balance(target: Member = null):
    user = target or author
    gold = store.wallet.get(user.id, 0)
    reply "💳 {user.name} has **{gold} gold**."
